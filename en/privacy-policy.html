Privacy Policy

This is an English translation for convenience. If there is any difference, the Japanese version prevails.

LB TAB Layers Chrome / Edge extension (the "Extension")

1. Information We Collect

The Extension uses users' personal information only to the minimum extent necessary.

The permissions the Extension uses, and what each one is used for, are as follows:

  • Tab information (tabs permission): Gets the URL, title and favicon of the tabs currently open and shows them in the side panel
  • Tab group information (tabGroups permission): Gets the state of Chrome's tab groups and uses it for display
  • Bookmark information (bookmarks permission): Syncs the tabs in the groups the user has saved to bookmarks. For duplicate detection and dead-link checks, it reads all of the user's Chrome bookmarks when the user performs those actions
  • Local storage (storage permission): Saves the user's settings (theme, group structure, notes, etc.) inside the browser
  • Browsing history (history permission): Used for the feature that lists today's browsing history in the side panel (PRO version only) and for suggesting frequently used sites. For suggestions, the history of the last 14 days is tallied only on this computer and is not sent outside
  • Favicons (favicon permission): Shows, next to saved pages, pins and frequently used sites, the site icons that Chrome has stored on this computer. They are not sent to any external service
  • Alarms (alarms permission): Used for the periodic license check (once a day), the check for syncing with bookmarks (every 5 minutes), and managing the end time of the focus timer
  • Side panel (sidePanel permission): Shows the tab management UI in Chrome's side panel
  • Site blocking (declarativeNetRequest permission): During Focus Mode, redirects sites the user has specified to a block page. The block rules are created locally and are not sent outside
  • Google account connection (identity permission): Used only when the user uses the spreadsheet integration, to access Google Sheets with the user's Google account
  • Downloads (downloads permission): Used to save screenshots and recordings as files to a location the user chooses. A screen for choosing where to save appears each time a file is saved. It is also used to save the images the user selects in "Images on this page" to an "LB-images" folder inside the Downloads folder (no save dialog appears for this). The browser fetches the images just as it does when the page is opened, and nothing is sent to us
  • Reading the clipboard (clipboardRead permission, optional): The browser asks for this permission only when the user turns on "Let me know if I have copied a URL" in Settings. It is used only to check whether a URL has been copied; the content is not saved or sent
  • Right-click menu (contextMenus permission): Used to show "Save to TAB Layers" in the right-click menu for web pages and links, and to save to the group the user picks
  • Adding processing to pages (scripting permission): Used, when the user performs the action, to take a full-page screenshot (scrolling down to the bottom while capturing) and to record with automatic scrolling. It is also used, when the user selects "Add to note" from the right-click menu, to read the selected text and put it into a note. In addition, only when the user performs the action, it is used to show an image's size and list the images on a page (reading where the images are and how large they are), to insert a note into an input field on the page, to change the volume of video or audio and put a video into a small window from "Now playing", and to collect and copy the URLs of the videos listed on a YouTube page. Nothing that is read is sent to us
  • Access to all sites (host permission): Used for the overlay sidebar, taking screenshots and thumbnails, automatic detection of RSS feeds, dead-link checks, attaching page text to the AI sidebar, linking notes to pages, and the badges that show unread counts for email and chat (by reading the number in the page title), for showing whether a page is already saved, and for checking the file size of images. The content of pages is never sent to us

2. Where Data Is Stored

Your data is stored inside the browser you use

Usage data such as the user's tab structure, group settings, theme settings (including the colors of an original theme), notes, Step Tasks (tasks for work steps, and templates) and feature-badge records is stored inside the user's browser through chrome.storage.local and Chrome's bookmark feature.

Page thumbnail images are saved only when the user turns them on in Settings (off by default), as small, shrunk-down images of the screens of pages the user has viewed, and only inside the browser the user uses. Pages such as email, banking and card, login and payment, and chat are never captured from the start. The user can add sites not to capture in Settings (when a site is added, any already-saved images that match it are also deleted). Images are not sent outside. Screenshots and recordings are saved as files on the user's PC when the user chooses to save them.

Screenshots and revision notes (captured images, the notes written on them, a video's playback position and title, and the page URL) are stored inside the browser the user uses (the Extension's storage) so they are not lost when the side panel is closed. When capturing a moment of a video, the Extension reads only the video's position and size on the page, its playback position and its title; anything shown on top of the video is hidden only at the moment of capture and restored right away. When the user opens a video file from their computer, it is played only inside the browser and is never uploaded. None of this is sent externally.

So they can be found in search, the URLs and titles of recently closed tabs (up to 50) are stored only inside the browser the user uses. Tabs in incognito windows are not recorded. Nothing is sent outside. When importing a file exported from another browser or extension (HTML, CSV, TXT), the file is read only inside the user's browser.

Only the following two things reach our servers.

  • The extension's installation ID (a randomly generated, anonymous identifier), for license verification
  • The content of feedback the user chooses to send (see 3-3)

If Chrome bookmark sync (Google account) is turned on, saved groups and tabs are synced by Google's services as Chrome bookmarks. This is a feature of Chrome itself.

3. External Communication

The Extension communicates with the following external services.

3-1. Loading UI resources

The following is used to display the UI, and no user data is sent.

  • Tabler Icons (cdn.jsdelivr.net): icon font

3-2. License management (PRO purchase feature)

To purchase PRO and verify licenses, the following information is sent to our server:

  • Destination: liquid-block.com (our Wix site)
  • Data sent: the extension's installation ID (a randomly generated, anonymous identifier)
  • Purpose: to check that the license is valid and to create Stripe payment sessions

Payments are processed on the secure payment page of Stripe, Inc. Credit card information does not pass through our servers.

3-3. Feedback (optional; only when the user sends it)

Only when the user sends it from the feedback form for extending the trial, the following is sent to our server (liquid-block.com):

  • Data sent: what was entered in the form (how the user uses the Extension, what they like, what they would like improved, and their rating), the number of days left in the trial, the extension version, and the installation ID
  • Purpose: to improve the product and to process the trial extension

3-4. Search assistance and search suggestions

When the user types in search, the typed text is sent to Google's suggestion service (suggestqueries.google.com) to get suggestions.

3-5. AI search feature (optional; only when the user turns it on)

The titles and URLs of saved tabs are sent to the AI engine the user has selected (Chrome built-in AI / Google Gemini / OpenAI / Anthropic Claude). If Chrome built-in AI is selected, processing happens inside the user's PC and nothing is sent outside. API keys are set by the user and stored only locally.

3-6. AI sidebar (optional; only when the user uses it)

The question the user types, and the text of the page or the selected passage the user chose to attach, are sent to the selected AI engine.

  • Chrome built-in AI: Processed inside the user's PC; nothing is sent outside
  • Google Gemini: Sent directly to Google (generativelanguage.googleapis.com) with the user's own API key. It does not pass through our servers

3-7. Spreadsheet integration (optional; only when the user turns it on)

With permission from the user's Google account, the list of saved tabs (group name, title, URL, ★ rank, tags and notes) is written to and read from the user's own Google spreadsheet through the Google Sheets API (sheets.googleapis.com). It does not pass through our servers.

3-8. RSS reader (optional; only when the user adds feeds)

The Extension accesses the URLs of the RSS feeds the user has added to get new articles. To show an article's thumbnail image, it may access the article's page to get the URL of the image.

3-9. Dead-link check (only when the user runs it)

When the user runs it, the Extension accesses the URLs of the target bookmarks to check whether the pages can be opened. The results are not sent to us.

3-10. Weather display

To show the weather on the pin bar clock, weather information is obtained from Open-Meteo (api.open-meteo.com). The only thing sent is an approximate location (latitude and longitude at the city level) estimated from the computer's time zone. Location information (such as GPS) is not used.

3-11. Add to Google Calendar (only when the user presses it)

Only when the user presses the "Add to Google Calendar" button in Step Tasks, the name of that task and its list of steps are passed to Google Calendar's event creation screen (calendar.google.com). The screen simply opens in the user's own browser, and nothing is sent to our servers. No sign-in or Google account permission is needed for this integration.

3-12. Pasting or dropping URLs (only when the user does so)

When the user saves a URL by pasting it into a group or dropping it onto one, and the URL has no title, the Extension connects to the page at that URL and reads the page title so that the page name can be shown. It connects only to the URLs the user pasted or dropped, and does not send login information (cookies). The title it reads is stored inside the browser the user uses and is not sent to us.

3-13. Copied-URL notice (optional; only when the user allows it)

Only when the user turns on "Let me know if I have copied a URL" in Settings and allows the browser's "Read clipboard" permission, the Extension checks whether there is a URL on the clipboard when the side panel is opened. It checks only whether a URL is there; it never saves the clipboard content or sends it to us or anyone outside. The permission is withdrawn when the setting is turned off.

3-14. Survey when uninstalling

When the Extension is uninstalled, a survey page on our site (tablayers.liquid-block.com) opens. The URL that opens the page contains only the extension version, the number of days since installation, and the display language. Answering the survey is optional. Only if the user answers, the reasons they chose, the text they entered, and the version and other items above are sent to us through Google Forms (Google LLC). Names, email addresses, browsing history and bookmark contents are not sent.

3-15. Adding to NotebookLM (optional; only when the user agrees)

The feature that adds pages and YouTube videos directly to a NotebookLM notebook works only after the user agrees to the explanation shown the first time. After that, the URLs of the pages or videos the user chooses, and the name of the target notebook (or the name of a new one), are sent directly to Google NotebookLM (notebook.google.com / notebooklm.google.com) using the user's own Google sign-in. To show the list of notebooks, the extension reads notebook names and source counts from NotebookLM. Nothing passes through our servers, and the extension does not store passwords or sign-in information. Consent can be withdrawn at any time in Settings. Without consent, the extension only copies the URLs and opens NotebookLM; nothing is sent.

3-16. Sharing to social media (only when the user presses a button)

Only when the user presses the X, Threads, Bluesky, Facebook or LinkedIn button (for example in the memo window), that service's post screen opens in the user's own browser, pre-filled with the text the user wrote and the page URL. The user decides whether to post. Nothing is sent to our servers.

3-17. Questions and contact (only when the user sends the form)

On the screen opened from "Questions & contact" in Help or Settings, only when the user presses "Send", the type they chose, the text they entered, the browser name and version, the operating system, the extension version and the display language are sent to us through Google Forms (Google LLC). What will be sent is shown on the screen before sending. We do not send your name, email address, browsing history or bookmark contents.

4. Sharing with Third Parties

The Extension does not provide, sell or share users' data with third parties. For payment processing, Stripe's privacy policy applies.

5. Deleting Data

When the Extension is uninstalled, all data in the Extension's storage (groups and tabs, notes, step tasks, today's history, thumbnails, screenshots and revision notes, settings such as the theme, and the license check result) is deleted automatically.

The following are kept because they live outside the Extension. You can delete them yourself at any time.

  • Groups and tabs saved to Chrome bookmarks (the "LB TAB Layers" folder, including its trash): delete them from Chrome's bookmarks
  • Downloaded files (screenshots, recordings, images and exported files): delete them as files on your computer
  • Data exported to Google Sheets (only if you connected it): delete it from Google Drive

6. Children's Privacy

The Extension is not aimed at any particular age group, and does not knowingly collect data from children under 13.

7. Changes to This Policy

This privacy policy may be updated as needed. If there are important changes, we will let you know through an update of the Extension.
